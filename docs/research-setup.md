# Setting up the CI research job

The job never sees a key in the repository, in a log, or in an artifact. Keys
are GitHub Actions secrets in the protected `research` environment and are
passed to the router only as environment variables.

## 1. Create three free keys

| Provider | Create a key at | Used for |
|----------|-----------------|----------|
| Google AI Studio | https://aistudio.google.com/apikey | Primary extraction (`auto:smart`) |
| Groq | https://console.groq.com/keys | Second, independent extraction |
| OpenRouter | https://openrouter.ai/keys | Failover when one provider is busy |

All three have free, no-card tiers. The router chooses the actual model; this
project does not hardcode provider model IDs.

Optional fourth: FreeInference (https://freeinference.org) or Cloudflare
Workers AI (needs an Account ID in addition to the token).

## 2. Put the keys in a local file, not in chat or git

```bash
mkdir -p /tmp/opencode
nano /tmp/opencode/free-llm-keys.env
chmod 600 /tmp/opencode/free-llm-keys.env
```

Contents:

```dotenv
GEMINI_API_KEY=
GROQ_API_KEY=
OPENROUTER_API_KEY=
```

Create a GitHub environment and secrets from that file:

```bash
gh api -X PUT repos/Valentjno/opencode-analysis/environments/research
for name in GEMINI_API_KEY GROQ_API_KEY OPENROUTER_API_KEY; do
  value=$(grep "^${name}=" /tmp/opencode/free-llm-keys.env | cut -d= -f2-)
  printf '%s' "$value" | gh secret set "$name" --env research
done
```

The commands above read each value from the file without printing it. After
setting the secrets, delete the local file if you want. GitHub keeps the only
copy.

Two more secrets are generated by the workflow, not by you: `FREE_LLM_API_KEY`
(the router's own bearer key) and `FREE_LLM_MASTER_KEY` (used to encrypt the
ephemeral router config). Set them once with any random values, for example
`openssl rand -hex 32`.

## 3. Run it

Manual first:

```bash
gh workflow run research.yml -F dry_run=true -F max_models=1
gh workflow run research.yml -F max_models=1
```

Inspect `public/data/research.json` and the workflow log. When it is clean,
uncomment the `schedule:` block in `.github/workflows/research.yml` and let the
12-hour cadence take over. The first runs use `max_models: 3`, then 5.

## 4. What the job does

1. Reads `latest.json`, `research.json`, and the locked manual overrides.
2. Picks up to 15 gaps from eligible models.
3. Searches DuckDuckGo, restricted to official vendor domains and orgs.
4. Fetches pages with SSRF, size and content-type limits.
5. Asks the router (`auto:smart`, then `auto:spread`, then `auto:reasoning`) for
   structured extractions. It reads `x-free-llm-provider` from each response so
   two different providers are required.
6. Verifies the exact quote and the agreement, then writes only `verified`
   values.
7. Commits only `public/data/research.json`.

Prompts contain only public model and benchmark names. Provider keys and the
router key are passed by environment, never as arguments, never logged. Router
request logging is disabled, the log file is deleted, and no artifact is
uploaded.

## 5. Rotation and revocation

Use dedicated keys for this job. If a key is suspected leaked, revoke it at the
provider, rotate the matching GitHub secret, and re-run the workflow. The router
pins each key to its provider host on first use and refuses to send it
elsewhere.

## Current live status

The dry runs on GitHub-hosted runners complete successfully but currently accept
zero values: Google AI Studio rejects the key from the runner's IP range
(`Invalid Auth key`), and the other free models either hit quota limits or
return prose that fails the quote verification. The schedule is therefore left
commented out and no `research.json` is published.

The same pipeline was verified locally with the same keys, so the blocker is the
providers' treatment of CI egress IPs, not the orchestrator. Options are:

- add a free provider whose tier allows GitHub Actions IPs;
- run the research job on a self-hosted runner;
- keep research as a local maintainer tool and commit the result manually.

Verification is deliberately strict: if a model will not provide an exact quote
naming the model, benchmark and number, no value is published.
